# Internationalization (i18n) Infrastructure

Phase 1 established the i18n architecture. Subsequent phases migrated UI
strings through this system. **No screens were redesigned and no business
logic changed** — only hardcoded text was routed through `t()` and the
`Intl`-based formatting helpers. All UI text flows through this system.

## Architecture

- **Library:** [`i18next`](https://www.i18next.com/) + [`react-i18next`](https://react.i18next.com/).
- **Single instance:** `src/i18n/config.ts` creates and initializes one i18next
  instance (singleton). It is imported once for its side effect and reused
  everywhere via `useTranslation`.
- **Lazy namespaces:** A custom backend (`src/i18n/backend.ts`) uses Vite's
  `import.meta.glob('./locales/*/*.json', { eager: false })`. Each
  `locales/<lng>/<ns>.json` becomes a code-split dynamic import, so a namespace
  is only fetched/parsed the first time it is used (`useTranslation('<ns>')` or
  `i18n.loadNamespaces`). Only the `common` namespace is seeded synchronously
  for every language to avoid a first-paint flash.
- **Interpolation & pluralization:** Standard i18next interpolation
  (`escapeValue: false`, since React escapes) and pluralization
  (`itemCount_one` / `itemCount_other`) are supported out of the box.
- **ICU (future):** The formatter is pluggable. To enable ICU message format
  later, add `i18next-icu` and `.use(i18nextIcu)` in `config.ts` — no component
  changes required. Deferred for now to keep the dependency surface minimal and
  avoid mixing pluralization syntaxes.
- **Type safety:** `src/i18n/types.ts` augments `i18next` with the resource
  shape, so `t('namespace:key')` is checked against real keys and the active
  namespaces are typed (`useTranslation('auth')`).
- **Formatting:** `src/i18n/format.ts` exposes `formatNumber`, `formatCurrency`,
  `formatPence`, `formatDate`, `formatRelativeTime`, and
  `currencyCodeFromSymbol` built on `Intl`. They default to the active
  i18next language, so locale-aware formatting needs no component rewrites.
  - `formatPence(pence, currency)` formats an integer minor-unit amount
    (e.g. `556` → `"£5.56"`). **Always** use this for wallet/request amounts
    stored as pence; never concatenate a currency symbol by hand.
  - `currencyCodeFromSymbol(symbol)` maps a display symbol (`£`, `$`, `€`,
    `₺`, `¥`) to its ISO 4217 code so `Intl.NumberFormat` can format
    locale-aware. Unknown/missing symbols fall back to `GBP`.
- **Language resolution (priority):**
  1. Authenticated user's saved preference — `getUserLanguagePreference()`
     (future-ready; returns `null` until preferences are editable).
  2. Browser language — `detectBrowserLanguage()` (honours `navigator.languages`).
  3. English fallback — `DEFAULT_LANGUAGE = 'en'`.
- **RTL readiness:** `applyDocumentDirection()` sets `dir`/`lang` on `<html>`.
  `RTL_LANGUAGES` already lists `ar`, `he`, `fa`, `ur`. Components should use
  logical CSS properties (`margin-inline-start`, `padding-inline`, etc.) so
  Arabic/Hebrew can be added later without a redesign. RTL is **not** enabled
  yet.
- **Bootstrapping:** `src/i18n/index.ts` exports `bootstrapI18n()`, called once
  from `src/main.tsx` before render. The app is wrapped in a single
  `<I18nextProvider i18n={i18n}>` — there are no duplicate providers.

## Folder tree

```
src/i18n/
├── backend.ts        # Vite glob lazy namespace loader (i18next BackendModule)
├── config.ts         # i18next init: languages, namespaces, interpolation, react
├── format.ts         # Intl helpers: currency, number, date, relative time
├── index.ts          # bootstrap + language resolution + RTL direction
├── types.ts          # typed resource augmentation (CustomTypeOptions)
├── i18n.test.ts      # focused infrastructure tests
└── locales/
    ├── en/           # common, auth, family, tasks, wallet, goals, rewards,
    │                # dashboard, approvals, settings, notifications, errors,
    │                # behaviour, profile, funds, requests, reversals
    └── tr/           # same structure, Turkish translations
```

## How to add a namespace

1. Create `src/i18n/locales/en/<ns>.json` and `src/i18n/locales/tr/<ns>.json`
   with the same keys.
2. Add `'<ns>'` to the `NAMESPACES` array in `src/i18n/config.ts` (for typing
   and documentation).
3. Add the `<ns>` shape to the `Resources` interface in `src/i18n/types.ts`
   (import the `en` JSON `typeof` and reference it for both languages).
4. Use it in a component: `const { t } = useTranslation('<ns>'); t('<ns>:key')`.
   The namespace loads lazily on first use — no central registration needed.

## How to add a language

1. Create `src/i18n/locales/<lng>/` with all namespace JSON files (mirror `en/`).
2. Add `'<lng>'` to `SUPPORTED_LANGUAGES` in `src/i18n/config.ts`.
3. Seed the `common` namespace for the new language in `config.ts`'s
   `resources` block so the first paint is instant (other namespaces stay lazy).
4. If the language is RTL, add its base code to `RTL_LANGUAGES` in
   `src/i18n/index.ts`.

## How to add new strings

1. Add the key to the relevant namespace JSON for **every** language
   (e.g. `en` and `tr`). Keep keys flat and dot-free; use the `nsSeparator`
   (`:`) to address a namespace: `t('auth:signIn')`.
2. For interpolation: `"greeting": "Hello, {{name}}"` → `t('dashboard:greeting', { name })`.
3. For pluralization: `"itemCount_one": "{{count}} task"`,
   `"itemCount_other": "{{count}} tasks"` → `t('tasks:itemCount', { count })`.

## How to use `t()`

```tsx
import { useTranslation } from '@/i18n'; // re-exported from react-i18next

function Example() {
  const { t } = useTranslation(['common', 'tasks']);
  return (
    <button>{t('common:save')}</button>
    <p>{t('tasks:itemCount', { count: 3 })}</p>
  );
}
```

Formatting helpers are imported directly:

```ts
import { formatCurrency, formatRelativeTime } from '@/i18n';

formatCurrency(9.99, 'USD');            // uses active language
formatRelativeTime(dueDate);            // "in 2 days" / "tomorrow"
```

## Canonical rules (enforced in cleanup)

- **Never call `toLocaleString()` / `Intl.*` directly in components.** Route
  every date/number/currency through `formatDate`, `formatNumber`,
  `formatCurrency`, `formatPence`, or `formatRelativeTime`. This keeps
  formatting locale-aware and consistent.
- **Never hardcode a currency symbol.** Use `formatPence(amount, currencyCode)`
  (or `formatCurrency`) and derive `currencyCode` from
  `currencyCodeFromSymbol(familyData.currency)`.
- **Translate every user-visible string, including `aria-label`, `title`,
  `placeholder`, dialog/menu/nav labels, and empty states.** Untranslated
  English is a bug.
- **Synchronous `i18n.t()` in lib code:** `src/lib/requestModel.ts` and
  `src/lib/reversalHistory.ts` call `i18n.t()` directly (not via the React
  hook). This is synchronous, so the relevant namespace **must already be
  loaded**. In tests that call these functions or render components using
  them, load the namespace first:
  ```ts
  import i18n from '../../i18n/config';
  beforeEach(async () => {
    await i18n.loadNamespaces(['requests', 'approvals', 'common']);
    await i18n.changeLanguage('en');
  });
  ```

## Tests

Focused infrastructure tests live in `src/i18n/i18n.test.ts` and cover
initialization, fallback language, browser-language detection, lazy namespace
loading, and the `Intl` formatting helpers. Run them with:

```bash
npx vitest run src/i18n
```

## Constraints

- UI strings are migrated through `t()`; **no business logic or behaviour
  changed** during cleanup.
- No language selector UI yet (resolution is automatic).
- No visual redesign; RTL is architecturally supported but not enabled.
- ICU formatting is deferred but the formatter is pluggable.
- `requests` and `reversals` namespaces were added in Phase 2E to hold
  request/approval and reversal-history copy respectively.
